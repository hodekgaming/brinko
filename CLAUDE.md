Voice-activated multi-agent AI desktop assistant for Windows. Python 3.11 + PyQt6.
Entry point: `python main.py`, or the desktop **BRINKO** icon (made by `python make_desktop_shortcut.py`: pythonw, no console, icon in `assets/brinko.ico`). Without a console, stdout/stderr go to `logs/brinko.log`. A named mutex keeps it single-instance (a 2nd launch focuses the existing window). Install deps: `pip install -r requirements.txt`.

## Architecture

Tool calls run as tasks so the receive loop never stalls; tools in `BACKGROUND_TOOLS` run as background jobs (return instantly, result is announced via a `[BACKGROUND JOB FINISHED]` text turn).
- `agent/background_jobs.py` — job manager (max 4 concurrent) feeding the HUD job cards + `background_jobs` tool.
- `ui.py` — PyQt6 HUD. **Nov 9 2026 restyle (user's WhatsApp reference video): deep ROYAL BLUE background (`_build_bg` radial gradient + still far stars + vignette, palette `C` is blue), the sphere is now a WHITE-HOT STAR (`_paint_sphere`: blue halo glow, cached `_star_core`, white core swelling with the voice, thin horizontal lens flare; must fit in 2.6 R for the mini orb), the particle cloud has CONSTELLATION LINES (`_ParticleCloud.e0/e1`: ~400 fixed 3D nearest-neighbour edges, drawn aliased), GLASS PANELS (`_glass`, `_panel_label`): MARKETS (BTC/ETH/SOL + 7d sparklines, CoinGecko public API every 10 min on a thread → `_MARKETS`), SYSTEM rings (CPU/RAM/battery, psutil every 2 s → `_stats`), right-column chat cards (last 5 you/brinko lines), VOICE CHANNEL bar bottom centre (voice name + state + scrolling waveform `_wave`); panels go through `_cached_panel` pixmaps; warp streaks capped at 0.4 (calmer). Paint ≈ 16–18 ms at 1280x760.** Older notes: JARVIS look (Nov 8 2026): black/navy, a translucent energy SPHERE (cached glow+body+latitudes sprite `_sphere_body`, rotating meridians, 6 noisy plasma strands, white core) inside a 3D PARTICLE CLOUD (`_ParticleCloud`, 1800 pts, numpy rotation/perspective; small dots aliased squares, big ones AA; while BRINKO speaks they become warp streaks drawn aliased — AA lines cost 10x). Accent colour per state, lerped (`_STATE_ACCENT`: cyan listening, bright cyan speaking, silver thinking, amber standby, gold ultra, grey muted). Left ACTIVITY column (`push_log`, every write_log line, newest types in), letter-spaced wordmark, thin status line, agent tag under the sphere (`flash_agent`), horizon glow + transcript bar (ChatOverlay, centred). Paint ≈ 13 ms listening / 20 ms speaking at 1280x760; timer 20 ms busy / 33 ms idle (leaves the GIL to the audio threads). The old pink agent-ring HUD was replaced entirely. Widgets must only be touched on the GUI thread — use the MainWindow signals.
- `actions/voice_focus.py` — per-app audio meters (pycaw): while another app plays sound BRINKO is in STANDBY (mic audio not sent). Ctrl+Alt+B (global RegisterHotKey) or orb tap open a talk window, duck other apps to 15%, keep-alive on user/BRINKO speech, restore after ~9s quiet. All COM work stays on its own thread.
- `actions/file_finder.py` — `open_file` tool: in-memory index of Desktop/Documents/Downloads/Pictures/Videos/Music/OneDrive (~35k items <1s), vocabulary-level fuzzy matching (fast), type/recency hints, AI synonym/translation expansion (CV→Lebenslauf) and AI pick only when ambiguous.
- `actions/smart_writer.py` — ghostwriter for emails (`compose_email`) and texts (`compose_text`): language/register detection (German + Sie/du), relationship-aware tone, medium-appropriate length, never invents facts ([placeholders]), uses memory. Uses `client.chat(..., smart=True)` (gemini-3.5-flash first, 14s hedge; thinking tokens count against max_tokens — keep limits high).
- `actions/send_message.py` — draft → read back → send flow (`_LAST_DRAFT` remembers it). Sending: open_app foreground (never Windows Search), Ctrl+F contact, Gemini-vision check that the open chat IS that person (aborts otherwise), clipboard paste (umlauts/emoji).
- `actions/email_agent.py` — no mailbox config → writes and opens a pre-filled Gmail compose URL (+clipboard); with config → drafts, `reply` (uses the latest email from that sender as context), read_recent.
- `actions/deep_think.py` — `deep_think` tool: hard questions go to the smart model; Live model speaks the short version.

## Hard-won lessons (don't regress these)
- DPI awareness must be set at the very top of main.py before Qt/pyautogui load, and `screen_find` must scale screenshot coords to pyautogui click-space — otherwise clicks land in the wrong place.
- Mic: MIME type must be `audio/pcm;rate=16000`; CHUNK_SIZE 1024; out_queue maxsize 200; never do heavy work (numpy) inside the sounddevice callback (causes input overflow).
- Reconnect: Gemini Live sessions end on their own (duration limit, 1006/1011 hiccups) — reconnect after 0.2 s if the session ran >30 s, exponential backoff (0.5→10 s) only for repeated quick failures (it used to always wait 3 s). Greeting starts when the speaker stream is running (`_play_ready`), weather is prefetched while connecting (`_wx_cache`).
- VAD: END_SENSITIVITY_LOW + silence_duration_ms=900 (1500 felt slow). The old 2.5 voice model needed thinking_budget=0 (2.6s → 1.4s); 3.x live models must NOT get a thinking_config. Big reasoning goes to deep_think.
- `HudCanvas._rot` must NOT wrap at 360 — its users rotate at 0.12x/-0.55x/1.6x and jumped every lap. It wraps at 360000 (a common multiple); each use applies its own `% 360`.
- Live transcripts arrive as sub-word fragments that carry their own leading spaces — concatenate them raw (`"".join`), never `.strip()` + `" ".join` (that was the real cause of "th e hu ngr y").
- BRINKO counts as speaking until PLAYBACK drains (`_play_audio` timeout), not until `turn_complete` — otherwise the mic reopens mid-sentence and Gemini hears its own voice. Echo cooldown 0.5s.
- The startup greeting must be sent as an INSTRUCTION (`[SESSION START — not something the user said] …` + facts) — sending the finished greeting text made the model treat it as user speech and reply to it.
- `open_app` understands intent: heuristics (exact/prefix/all-words/contains/difflib) then an AI pick from the installed-apps list; AI answers are learned in `config/app_aliases.json`.
- The single-instance mutex lives in `main()` (`_ensure_single_instance`), not at import time — otherwise importing main for tests exits while BRINKO runs. If the running copy is older than the newest code file, a new launch WM_CLOSEs it and starts fresh (the icon used to refocus a stale BRINKO forever, so fixes never loaded).
- The mic callback ALWAYS sends a chunk: real audio when listening, zeros when muted/standby/BRINKO talking. Sending nothing makes Gemini Live close the session (1008 "client inactivity") → reconnect loop.
- Closing the window runs `voice_focus.shutdown()` (restores ducked app volumes) then `os._exit(0)`.
- Get-StartApps lists desktop programs as `{KnownFolderGUID}\rel\path.exe`; `shell:AppsFolder` can't launch those — `_target_for_appid` resolves them to the real exe via SHGetKnownFolderPath. Index cache is `config/app_index_v2.json` (bump the name if the entry format changes).
- Gmail IMAP folder names like `[Gmail]/Sent Mail` must be double-quoted (`_imap_select` wrapper).
- `google.generativeai` is deprecated — use `google.genai` only.
- `or_client` loads the OpenRouter key lazily — importing it must never require api_keys.json, or first-run setup can't appear.
- Always verify names resolve at runtime, not just `py_compile` (a missing `import time` once crashed every session).
- OpenRouter free vision models 404/rate-limit often — vision (screen_find) needs a more reliable path (Gemini vision).

## Workflow
- Test by actually running `python main.py` and reading the console output.
- Never commit `config/api_keys.json`, `config/email_config.json`, or `config/remote_token.json` (they hold secrets).
